# ATHLETEN SECURITY POLICY

## Reporting a Vulnerability

Nova Code welcomes responsible reports of security vulnerabilities affecting AthleteN.

Please report suspected vulnerabilities privately through:

**Security contact:** [INSERT OFFICIAL SECURITY EMAIL]

Do not publicly disclose credentials, private keys, personal data, exploit details, or other sensitive information before Nova Code has had a reasonable opportunity to assess and address the issue.

## Include When Possible

- affected feature or component;
- a clear description of the suspected issue;
- steps to reproduce in an authorised environment;
- security impact;
- relevant logs or screenshots with secrets and personal data removed; and
- a safe method for Nova Code to reproduce the issue.

## Good-Faith Testing

Testing must be limited to systems and accounts for which the tester has explicit authorisation. Do not intentionally access, alter, delete, extract, disrupt, or expose another person's data or resources.

## Secrets and Personal Data

Never include passwords, API keys, tokens, private keys, database credentials, or unnecessary personal information in a vulnerability report.

If sensitive information is accidentally exposed, notify Nova Code privately and avoid further access or disclosure.

## Scope

This policy covers AthleteN systems that Nova Code expressly identifies as in scope. Third-party infrastructure remains subject to the relevant provider's security and vulnerability-reporting process.

## Response

Nova Code will assess reports based on severity, reproducibility, affected users, exploitability, and other relevant factors. Response timing may vary.

## Legal Notice

Nothing in this policy grants permission to access systems outside the reporter's existing authorisation. This policy does not waive legal rights or remedies, except to the extent Nova Code expressly confirms otherwise in writing.
